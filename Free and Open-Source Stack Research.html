A complete tech stack that costs ₹0 — and where the free ends

The $0 architecture in one view

Two homes for everything: Cloudflare’s free edge for the public-facing parts, and one free always-on VM for the heavy parts. Everything else hangs off those two.

Cloudflare Pages / Workers / R2
Frontends, edge APIs, file hosting. Commercial use allowed on the free plan, hard caps, no surprise bill.
One Oracle Cloud Always Free ARM VM
2 OCPU / 12 GB RAM, 200 GB disk, 10 TB egress (halved 15 Jun 2026). Runs Docker Compose: Postgres + pgvector, n8n or Windmill, Postiz, Umami, Uptime Kuma, Langfuse, Ollama (small models only). The only true free always-on server.
LLM fallback chain
Groq → Cerebras → Gemini Flash → OpenRouter :free → Cloudflare Workers AI for burst and quality; local Ollama for private, cheap bulk work.
Media pipeline
Kokoro (Apache-2.0) for voice, FFmpeg + HyperFrames (Apache-2.0) for video, FLUX schnell / klein for images.
Scheduling
GitHub Actions cron (public repo = unlimited standard-runner minutes) + Cloudflare Cron Triggers.
Selling
Polar / Lemon Squeezy (5% + $0.50, merchant-of-record) globally; Razorpay Payment Links (2% + GST, ₹0 setup) in India. Percentage-only, $0 upfront.

Do not build on: Vercel Hobby for anything commercial · XTTS or F5-TTS for monetised video · FLUX.1 dev for commercial images · n8n as a tenant-facing SaaS feature · Remotion once you hire a 4th person · scraped LinkedIn / Indeed jobs. Each is explained in the layers and flags below.

(h) Social publishing via official APIs

Meta — Instagram Graph / Instagram Platform API. A Professional account only (Business or Creator) — personal accounts cannot publish via API at all. Two login paths: Instagram Login (no Facebook Page needed; permissions instagram_business_basic + instagram_business_content_publish) or Facebook Login (the IG account must be linked to a Facebook Page; instagram_content_publish etc.).

Your own account: you can develop and test in app Dev Mode without full review. Publishing for other people’s accounts requires Meta App Review (per-permission screencast submissions; guides report 2–4 weeks per submission) plus business verification.

Flow: media must sit at a public HTTPS URL (use R2) → create a media container → poll until FINISHED → media_publish. Carousels of up to 10 items count as one post. Cap: 100 API-published posts per rolling 24 h per account. No API fee is published.

YouTube Data API v3 — quota changed, and sources conflict. OAuth 2.0 with the youtube.upload scope is required to upload (an API key cannot upload); custom thumbnails need a verified channel.

Older / official-style guides (still ranking) say 10,000 units/day per project, videos.insert = 1,600 units (≈6 uploads/day), search.list = 100, reads = 1, writes = 50, reset at midnight Pacific, no paid tier — increases only via an audit/extension form. Newer Oct 2026 guides reading the current method docs say videos.insert and search.list moved to dedicated buckets (~100 calls/day each), separate from the 10,000-unit pool, after a Dec 2025 / 1 Jun 2026 change.

The unverified-project private-lock is also in dispute: the long-standing rule (projects created after 28 Jul 2020) locked unverified-project uploads to private with no appeal until a YouTube API compliance audit; an Oct 21 2026 check of the current videos.insert docs says uploads are no longer restricted to private, while other Oct 2026 guides still instruct passing the audit first.

Action — do not guess: check your own Google Cloud Console quota page and the current videos.insert reference before designing the cadence; submit the API audit / quota-extension form early anyway if you want higher quota or to publish for others, and test one upload’s final privacy status in Studio. Either regime easily supports a sane cadence of 1 long-form video/day plus Shorts — quota is not the binding constraint; Partner Program policy (next section) is.

For a solo own-account pipeline, Postiz is arguably overkill versus a small Python publisher — choose it if you want a calendar UI on day 1

Never use browser-automation / cookie-based “unofficial” Instagram or YouTube uploaders for a business channel — they violate platform terms, break constantly, and risk the account. Official APIs only.

YouTube policy: what an “automated channel” gets wrong

Primary source, read live on 3 Nov 2026: YouTube Help — Channel monetization policies, and the GenAI disclosure page. This is the one section of the research verified against the official page directly.

The rules, closely paraphrased from the official wording. The YouTube Partner Program requires content to be your original creation; borrowed content must be changed significantly; and content must not be mass-produced, generic, repetitive or manipulative — it must be made for viewers’ enjoyment or education, not solely for views. Reviewers judge the channel as a whole: main theme, most-viewed videos, newest videos, biggest watch-time videos, titles/thumbnails/descriptions, and the About section.

Reused content = repurposing content already on YouTube or another online source without significant original commentary, substantive modifications, or educational/entertainment value. This applies even if you have permission from the original creator — it is separate from copyright, permission and fair use, so zero copyright claims does not mean you pass.

Inauthentic content (renamed from “repetitious content” on 15 Jul 2025 — a clarification, not a new ban, and no change to the reused-content policy) covers generic, repetitive, template content, now explicitly including the examples below.

Consequence: if videos violate the policy, or reviewers “cannot clearly tell you made the content,” monetisation may be removed from the entire channel, not just one video.

Official examples of what is NOT allowed to monetise

  1. AI-generated content made with generic/unoriginal templates giving the impression of mass production, without the creator’s original, authentic insights or perspective.
  2. Image slideshows, templated storylines, or scrolling text with minimal or no narrative, commentary or educational value — the classic “stock photos + TTS reading a script” video.
  3. Content that exclusively features readings of other materials you did not create (text from websites or news feeds read aloud by TTS).
  4. Clips/compilations edited together with little or no narrative; short videos compiled from other social sites; content uploaded many times by other creators; promotion of others’ content (even with permission); content copied from another source without substantive modifications.
  5. Similar/repetitive videos with low educational value, commentary or narrative, or minimal variation — the same characters, situation and outcome templated across videos.
  6. Songs only pitch/speed-shifted; collections of songs (even with permission); mostly non-verbal reactions without voice commentary.
  7. AI personas presented as experts on sensitive topics — an AI “doctor” giving medical advice, AI podcast hosts giving financial/investment advice, AI personas giving legal advice: not monetisable at all.
  8. Unsatisfying/off-putting formulas: stitching unrelated AI clips for shock value, deceptive realistic imagery (fake celebrity death or disaster), repetitive distress/manipulative templates.
  9. Separately from monetisation: fake engagement and artificial inflation are banned, and the Community Guidelines and copyright rules apply in full.

What IS allowed

Critical-review clips; reaction videos with your commentary; edited footage with a storyline plus commentary; a scene with rewritten dialogue or a changed voiceover; sports replays where you explain the moves; content primarily featuring the creator; reused material where the creator is visible or explains how they added to it; edits with substantive audio/visual effects unique to the channel. A series format with the same intro/outro is fine provided each video’s substance is materially varied, with a distinct storyline, focus or concept. Using AI tools is not disqualifying — the reused-content FAQ says AI-using channels can still monetise if the content is clearly original.

GenAI disclosure — separate from monetisation

You must disclose when AI meaningfully creates or alters photorealistic content: a real person appearing to say or do something they didn’t, altered footage of a real event or place, a generated realistic scene that didn’t occur, or AI music that is the main focus — via Studio → Attributes → “AI use: Yes” at upload. Disclosing alone will NOT limit your audience or monetisation eligibility. No disclosure is needed for AI help with an outline, script, thumbnail or title, captions, colour/lighting, filters, or cloning your own voice. Repeated failure to disclose realistic AI can lead to YouTube applying labels itself, content removal, or Partner Program suspension.

A compliant faceless-channel workflow on the $0 stack

  1. Original research and script per video — your own angle, structure, examples and opinions, from primary sources; never a paraphrase or read-aloud of one article or another video. Keep your research notes and script drafts — they are evidence you made it, if the channel is reviewed.
  2. Original narration — a Kokoro voiceover of that script. An AI voice is fine; the script’s originality is what is judged. Vary structure, pacing, examples and visuals per episode — no identical template with the nouns swapped.
  3. Original visuals, not a slideshow — your own HyperFrames/Manim animations, charts drawn from your data, screen recordings of your own demos and code, and licensed stock as supporting B-roll under your commentary, with substantive editing (callouts, zooms, diagrams, chapter structure) that is visibly unique to the channel.
  4. A human editorial pass before publish — a person checks facts, adds a personal insight or example, and rewrites the title/thumbnail (your own FLUX / Penpot / HTML design, not a copied thumbnail). Automation prepares; it does not publish unreviewed at scale.
  5. A sane cadence — e.g. 2–3 long-form videos per week that you can actually make distinct, plus Reels/Shorts cut from your own long-form (not compilations of others’ clips).
  6. Disclose correctly — tick AI use = Yes if any photorealistic AI scene, person, or music-as-focus appears; otherwise script/TTS/animation assistance alone does not require it. When in doubt and it’s realistic, disclose — disclosure costs nothing.
  7. Avoid the hard bans — no AI-expert personas giving health/finance/law advice, no re-uploads or compilations, no TTS readings of web text, no mass-producing 10 templated videos a day. Build the channel’s About page and a consistent original format so a reviewer can clearly tell you made the content.

Flags: not actually free, not actually open source

Sixteen claims you will meet in blog posts and marketing pages that do not survive a licence or pricing-page check. This is the section to re-read before adopting anything new.

1 · Remotion
Source-available, not open source. Free only for teams of ≤3 people; a $100/mo minimum Automators plan applies at 4+.
2 · n8n
Fair-code / Sustainable Use, not open source. Free only for your own internal use; tenant-facing or embedded use is paid.
3 · Vercel Hobby
Non-commercial only. Ads or payments breach the terms — the fix is Pro at $20/seat/mo, or moving to Cloudflare.
4 · Railway / Fly.io
No real free tier — a trial credit and trial hours, respectively. Anything always-on exhausts them.
5 · Render Free Postgres
Expires after 30 days, and the free web service sleeps after 15 minutes idle. Demo infrastructure, not production.
6 · XTTS-v2 & F5-TTS weights · edge-tts
XTTS and F5 weights are non-commercial. edge-tts is an unofficial cloud client, not a local/open-source service, and carries a Microsoft terms risk.
7 · FLUX.1 / FLUX.2 dev
Non-commercial licence. Only schnell and klein-4B are Apache-2.0 and safe for products.
8 · “Open source” that isn’t
Llama models are open-weight under a custom licence, not OSI open source. Phoenix (eval) is Elastic Licence. Postiz Cloud, Plausible Cloud and Trigger.dev Cloud have no free hosted tier despite “open-source/free” headlines — free means self-host.
9 · Hugging Face Inference · GitHub Models
HF’s free inference credit is $0.10/mo or reportedly zero now — not a usable free API. GitHub Models was retired in Jul 2026.
10 · Gemini Free / OpenRouter Free
Free in price, paid in data and conditions: Gemini free content may be used to improve Google’s products; OpenRouter’s useful 1,000 RPD requires a $10 purchase, and free-model prompts may be logged upstream.
11 · Gumroad’s “10%”
Actually 10% + $0.50 plus 2.9% + $0.30 processing — ≈13%+ on small tickets — and 30% on Discover sales.
12 · “Zero-MDR UPI = free payments in India”
False via any gateway: Razorpay still charges its 2% + GST platform fee on UPI transactions.
13 · Oracle “4 CPU / 24 GB free forever” guides
Outdated since 15 Jun 2026 — it is now 2 OCPU / 12 GB, plus card verification, capacity shortages and idle reclamation.
14 · YouTube “1,600 units / 6 uploads a day” guides
May be outdated after the Dec 2025 / Jun 2026 dedicated-bucket change (~100 uploads/day in current method docs). Verify in your own console.
15 · Piper “MIT”
Outdated for the current GPL engine, and each voice carries its own licence — check the voice you plan to use.
16 · Canva / Pinecone / PostHog Cloud / Sentry
Useful free tiers, but proprietary. They belong in a stack only where the self-hosted or open-source path is named alongside them.

Two directories checked, neither changes the stack. free-for-dev (141,750 stars) confirms the core picks — Cloudflare, Oracle, Supabase, Gemini — and adds two useful supplements: Tavily (1,000 requests/mo, no card — class C) for research/web grounding, and Kaggle Notebooks (30 GPU hrs/week, P100 or 2×T4; no card, phone verification instead — class D) as the free burst-GPU escape hatch. Tabworthy is a general-interest discovery directory (514 sites, mostly games and curiosities) — a serendipity feed, not a dev-stack source. API-engineering tools (class A, with a hard boundary). reverse-api-engineer (MIT) captures a site’s network traffic to a HAR file and generates a typed API client; REA (MIT per Oct 2026 coverage) packages reverse-engineering tools for coding agents. REA’s star counts in Oct 2026 coverage conflict wildly (~96k to ~278k within weeks) — treat popularity claims as unverified; its own SECURITY.md warns it “is not a sandbox,” and fake “REA zip downloads” have appeared — only use github.com/morluto/rea, rea.tools, or the npm package rea-agents.
